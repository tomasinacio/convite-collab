### Keyframe Recipe (CSS only, transform + opacity):

```css
.leaf {
  /* Two comma-separated animations: sway + fall */
  animation: leaf-sway 6s ease-in-out infinite,
             leaf-fall 10s ease-out forwards;
  transform-origin: 50% 100%; /* rotate from lower corner for natural pivot */
}

@keyframes leaf-sway {
  0%, 100% { transform: translateX(0px) rotateZ(0deg); }
  50% { transform: translateX(35px) rotateZ(20deg); }   /* sway right, tilt */
  50.1%, 100% { transform: translateX(-30px) rotateZ(-15deg); } /* sway left, opposite tilt */
  /* Cycle repeats; period ~6s for calm phone motion */
}

@keyframes leaf-fall {
  0% { opacity: 1; transform: translateY(0px) rotateZ(0deg) rotateY(0deg); }
  20% { opacity: 1; transform: translateY(20px) rotateZ(10deg) rotateY(5deg); } /* start fast */
  50% { opacity: 1; transform: translateY(500px) rotateZ(30deg) rotateY(15deg); } /* constant speed */
  80% { opacity: 1; transform: translateY(800px) rotateZ(35deg) rotateY(20deg); } /* approaching ground */
  100% { opacity: 0; transform: translateY(860px) rotateZ(40deg) rotateY(25deg); } /* fade out */
}
```

### Critical timing details:

- **Vertical axis**: `ease-out` (cubic-bezier(0, 0, 0.58, 1.0)) — starts fast, slows toward ground; **not** uniform ease-in-out
- **Rotation**: `rotateZ` swings ±20–30° with a sine-like profile; rotation **lags** horizontal sway by ~¼ period (right-swing → clockwise rotation, left-swing → counter-clockwise)
- **rotateY**: subtle ±5–10° flip every few seconds; changes sign to avoid constant-direction monotony
- **Sway period**: ~6s for a calm phone leaf (fall time ~10s → sway period ≈ 0.6× fall time)
- **Horizontal amplitude**: 30–40px from center; large enough to see, small enough to feel gentle
- **Opacity fade**: starts at 1, uses ease-out timing; ends at 0 — **no linear fade**

### What makes leaf animations look "oof" (cheap/robotic):

| Anti-Pattern | Why it fails |
|---|---|
| Uniform ease-in-out on `translateY` | Constant acceleration/deceleration feels mechanical, not physical |
| Rotation in constant direction (always clockwise) | Predictable, lacks the occasional counter-flip a real leaf makes |
| Constant sway period (same every cycle) | Boring; real leaves vary slightly due to air turbulence |
| Linear fade from 100%→0% at end | Looks like a "fade-to-black" transition, not a leaf settling |
| No rotation lag between sway and spin | Sway and rotation in phase feels synchronized/robotic; lag by ~¼ phase feels natural |
| Linear timing function (even `linear()`) | Constant speed feels like a slide, not a fluttering/tumbling leaf |

### Start & End:

- **Fade in**: leaf starts with `opacity: 0; transform: translateY(-20px) rotateZ(-10deg);`, then animation begins from 0% with opacity rising to 1 over first 20% of keyframe duration
- **Settle or fade out**: at 100% the leaf has `opacity: 0` and is positioned at ground level; **do not** use `animation-iteration-count: infinite` if you want a single leaf to come to rest — use `forwards` fill-mode or trigger a one-shot animation

### Repeat spacing:

- For multiple leaves, stagger start delays using `animation-delay` (1.2s, 1.5s, 1.8s, 2.1s…) so they don't all align in phase — this avoids the "uniform rhythm" that the owner calls "oof"
- Vary fall durations slightly (9.5s, 10.2s, 11s) so periods don't lock together

### Performance:

- Only `transform` and `opacity` are GPU-accelerated — keep animation to those properties
- Avoid `box-shadow`, `filter`, or `width`/`height` animation on the leaf element
- Use `animation-fill-mode: forwards` for one-shot; `infinite` for continuous fall
