## How to work fast without wasting tokens (user, 2026-11-11: "You can instruct agents to work faster, but not much more inefficiently in quality and tokens")

- Edit the readable source `comps/prototype.v14.src.html` and the build script; never open or print the 4 MB single file. Read only the line ranges you need.
- Plan all edits first, then apply them in one pass; build once per round, not after every edit.
- Send independent tool calls in the same message (captures at several sizes, asset cuts, lint, `image_quality.py`).
- The user clarified (2026-11-11): more subagents may be created to work in parallel, not to hurry them. Lanes, each an Opus 5.5 high agent with its own files so they never edit the same file: lane A the closed front page (task 11): art, `comps/art/v14_front.py`, and a CSS block delivered as `comps/v14-front.css` plus the asset files; lane B the open page (tasks 1 to 10), owner of `comps/prototype.v14.src.html` and the build; lane C asset cut-outs and fits for lane B (citrus branch turned and matted, dogs enlarged and placed on the paper, bouquet prompt), delivering files and a CSS snippet, no edits to the page. The main session merges A and C into B with one build and does the measuring. Each lane reads only what it needs and reports in under 300 words.
- Reuse the existing captures and measurement scripts in `comps/art/perf/` and the scratchpad `ref/`; do not re-capture the demos.
- Take frames only at the times the checks need; look at contact sheets (several frames in one image) instead of many single images.
- Measure performance once per round, quiet machine, not after each tweak; use the quick idle check in between.
- Do not spend effort on polish that the user has not asked for; quality of the asked items comes first, and no step may skip a check to save time.
